CareGraph — 团队设计 & 作战卡

JacHacks SF · 2026-07-26 · 提交截止 19:15 硬截止（17:50 必交 Devpost 草稿）· 现在 ~11:30，剩 ~7.5 小时

30 秒版

一句话：挂在 Alzheimer's 患者胸前的一台旧手机自动听、自动记：对话由浏览器语音引擎转成文字（系统不录制、不存储任何音频，只保留文字），攒批交给 LLM 抽取，长成一张"她还记得什么"的记忆图谱。图谱自动检测衰退、自动报警、自动起草交接简报——照护者只做最后确认，医生打开就是完整病程趋势。人不再负责记录，只负责签字。

Tagline：See what she still remembers — and know the moment it starts to fade.

为什么能赢：① 全自动闭环：感知→抽取→检测→起草，人只出现在确认环节；② 医疗+照护域 = 本系列最高产获奖域（上届近半获奖项目：MediGraph、CONSILIUM、Persist、PharmaGraph、Drowzie——pitch 里报项目名，别报统计数字）；③ 架构就是 Jac 官方招牌范式（typed 图 + walker 议会 + byLLM 只在边界），同时押 3 个奖：Social Impact + Best Use of Jac + Best JacHammer。

故事（demo 开场 20 秒念这个）

"美国有 690 万 Alzheimer's 患者，1100 万家人在照护他们。没有人能准确回答：妈妈比上个月忘得更快了吗？等家人'感觉不对'时，往往已经晚了半年。

CareGraph：挂在胸前的一台旧手机静静听着她一天的对话——音频不出设备，只有文字进入她的记忆图谱。图谱自动生长、自动报警（'重复提问这周从 3 次涨到 11 次'）。交接班时 AI 已把简报起草好，照护者只需逐条确认。医生打开趋势页，看到的是完整病程曲线，不是家属一句模糊的'好像更严重了'。人不再负责记录，只负责确认。第一次，家人能亲眼看见亲人还记得的世界——以及它正在哪里褪色。"

三层结构（队内讨论定稿：数据质量逐层精炼，全程时间轴）

L1 患者随身端 —— 原始数据层（全自动）。一台旧手机挂胸前，网页只有一个按钮：长按开启，再长按关闭——患者随时可以关掉（这是尊严设计细节，不要在答辩里当"有效同意"讲：对认知障碍患者，开关不构成同意；同意来自监护人/POA 授权 + 佩戴明显标识）。开启时 Web Speech API 把对话连续转成文字（患者和任何人的对话都记）；如实口径：语音识别由浏览器引擎完成（Chrome 走云端识别），我们的系统不录制、不存储、不上传任何音频文件，只保留识别文字（roadmap：换 whisper.cpp 全本地识别）。文字攒批（每 5 分钟或一段对话结束）→ byLLM 一次性批量抽取，顺带拿到对话级衰退信号：同一个故事一次对话讲 3 遍、没认出来访的老朋友、答非所问。注意：浏览器的连续识别会周期性自停，代码里必须 onend 自动重启（demo 没问题，"戴一整天"是 roadmap 说法）。

L2 家属/照护者端 —— 人类精修层（半自动）。家属和照护者注入自己的观察（语音/文字补录），并负责两种报告：① 每日报告——全自动生成、自动存档；② 交接报告——换班/交接时点一下，AI 起草，人逐条 review 确认后保存。人不生产流水账，只批准结论。

L3 医生层 —— 临床报告层。就诊前一键生成医生版报告：完整病程趋势 + 关键事件时间轴 + 数据来源标注。（医生的专业化输入今天不做，进 roadmap——多一类角色 = 多一套表单和权限，demo 收益低。）

Jac 加分点：每个节点带来源标签（L1 wearable / L2 human / L3 clinical）和相应置信度权重——"分层数据质量"直接建模成 typed 图的属性，评委一眼看到这是图原生设计，不是套壳。整套系统 = 患者的基于时间轴的记录与报告系统：原始 → 精修 → 临床。

Demo 数据 = 预置 7 天种子数据（埋好衰退弧线）+ 一个现场活镜头：队友戴着手机说"Emma 周日要来看你"，大屏图谱当场长出新节点。历史靠种子，魔法靠这 10 秒。

摄像头方案（胸前拍照 / 远程监控式）今天不做，pitch 里只当 roadmap 提一句。三个理由：① 评委答辩必炸——对无法自主同意的患者做连续拍摄，还会拍到访客和其他患者，"监控摄像头"framing 正中 surveillance 质疑的靶心；音频挂坠是"陪伴"，摄像头是"监视"，故事光谱完全不同。② 技术成本翻倍（vision 模型、照片管道），demo 收益却几乎为零——活镜头用语音已经足够震撼。③ 手机浏览器锁屏后台会被杀，"网页当可穿戴"本身只在亮屏时可靠，demo 够用，加摄像头只是加故障点。

架构（分层，谁写哪层见分工表）

核心设计原则（评委会问，全队口径一致）：医疗判断不交给 LLM。衰退检测 = DriftWalker 在图上数边、比时间窗（确定性、可复现、可指出依据哪条边）；byLLM 只做两端翻译。一句话回答"AI 误诊怎么办"："我们不诊断，我们只把照护者自己记下的事实变得可见；每个报警都能点开看是哪几条记录触发的。"

Fintech/Open故事里没有钱的角度，硬凹会稀释 pitch；"Open 什么都收"意味着它是第二拥挤的池子。

开工前必须统一的 7 件事（你没想到的都在这）

  1. Demo 脚本先行：先写 1:30 视频脚本，再决定做什么功能。不在 demo 路径上的功能一律不做。
  2. 种子数据 = 情感弹药：7 天混合语料（随身端对话转写片段 + 交接补录），埋好衰退弧线——第 5 天开始叫错孙女的名字、同一个故事一次对话里讲 3 遍。B 花 30 分钟精心写，值。
  3. 伦理答辩预案（评委必问）："这是监控吗？"→ 主口径按顺序：① 家属/监护人（POA）授权（对认知障碍患者这才是有效同意，别拿长按开关当同意）；② 佩戴有明显标识，访客可见；③ 系统不录制不存储任何音频，只保留识别文字（识别由浏览器引擎完成，Chrome 为云端识别——被问就如实说，roadmap 是 whisper.cpp 全本地）；④ AI 只起草、人确认，报警是提示不是诊断（不碰医疗器械红线）；⑤ 可私有部署。撞车答辩（评委说"记忆图 GraphClaw 做过了"）：一句话——"GraphClaw 帮 agent 记住事实，CareGraph 测量一个人遗忘的速度：同一批 walker 在时间窗上重跑做纵向退化检测，这是监测系统不是记忆助理。"
  4. 合规 checklist：repo 公开且首 commit 在 10:45 后 ✓ 代码 ≥40% Jac（前端刻意保持轻量 vanilla JS 保护占比）✓ star jac repo（全队都去点）✓ 视频按 ≤90 秒制作（guide 没写上限，以 Devpost 表单为准，90 秒在任何上限下都安全）。⚠️ 官方原话"detailed rubric will be shared on Discord"——立刻去 Discord 拿细则，核对：Use of Jac 是否有最低分门槛、视频长度、Best JacHammer 判法。
  5. 风险 + fallback：① byLLM runtime bug（上届 Persist 踩过，直连 API 绕过照样获奖；Best Demo 得主 PharmaGraph 甚至 demo 路径全用确定性逻辑）→ 我们留了 CAREGRAPH_MOCK_LLM 保险丝；② Web Speech 要 secure context——手机连局域网 http 拿不到麦克风，方案 = cloudflared HTTPS 隧道 / jachammer 部署地址 / 兜底在演示笔记本 localhost 开 patient.html（localhost 算 secure context）；③ 浏览器连续识别会自停，代码已做 onend 自动重启；④ Jac 语法只用 docs/recon 里验证过的写法 + jac guide 离线手册，别赌冷门语法。
  6. 明确不做：摄像头/拍照、锁屏后台运行、native app、登录/多租户、医生专业输入、真实患者数据。有人想加 = 指着执行计划表最后一行拒绝。
  7. "完成"的定义：18:40 时哪怕一半功能是 stub，1:30 视频里的路径必须丝滑。视频路径神圣不可侵犯，其他一切可牺牲。
